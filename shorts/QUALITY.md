# 共通制作・検品ルール

この文書の時間・文字サイズ・余白は、このフォークで試作を始めるための仮の設定です。普遍的な最適値、投稿先の公式規格、再生数の保証ではありません。ユーザーの指定と実物の確認を優先します。

## 1. 原稿と公開範囲

- 原文と編集した台本を分けて保存する。省略・順番変更・創作したセリフを制作メモに記録する。原文維持の依頼なら意味・数値・英文・正解を勝手に変えない。
- 架空の人物・会話・診断は架空と分かる表示にする。実在の相手の証拠のようには見せない。笑いのための数字も統計や実測値と混同させない。
- 英語解説・商品機能・現在の価格などの正確さは、演出スキルとは別に確認する。確認できないことは断定しない。
- 公開リポジトリに生徒情報、私的なメッセージ、秘密鍵、個人アカウントの画面を入れない。素材の利用条件を確認する。

## 2. 初期仕様

未指定時は縦型1080×1920・30fps・無音でも理解できる構成を試作する。尺は原稿から決める。まず20〜45秒程度を検討するが、読む時間が足りなければ短文化・分割・尺延長を選び、速送りで解決しない。

ナレーションは指定がなければ必須にしない。BGM・効果音も任意。有料API、素材購入、外部投稿、広告配信、公開デプロイは、この制作ガイドを読んだことだけを根拠に実行しない。

## 3. 日本語と英文の組版

主見出し72〜96px、本文56〜68px程度を出発点にする。小さいラベルは40px程度から検討する。重要なオチ・答え・条件を注釈サイズへ逃がさない。書き出し後、幅360px程度のスマホ表示相当でも確かめる。

日本語は意味のまとまりで改行する。例えば「手伝わない／選択肢を確保」と「手伝わない選択肢／を確保」では読み味が違うので、文字数だけで切らない。句読点・閉じ括弧が行頭に来る、話者名だけが孤立する、重要語の途中で改行される状態を直す。

英語は単語内部を切らず、句・節の区切りを優先する。比較問題では２つの英文を消さずに保持する。１文字ずつの演出は短い強調語に限定する。英文の語数基準を、そのまま日本語の文字数基準として使わない。

## 4. 読む時間と「間」

文章の登場時間と、完全に読める状態で保持する時間は別に扱う。台本に「登場開始」「登場完了」「次の文章が増える時刻」「退場」を記録する。

読み時間の仮見積もりは、新たに読む日本語文字数をNとして、完全表示後に `max(1.4, 0.8 + N / 7)` 秒程度。これは機械的な合否基準でも読解速度の実証値でもない。文章の難しさ、既出の文脈、絵との同時理解、語学学習の負荷に応じて伸ばす。英語学習は語数だけで時間を確定しない。

オチ前の間は0.4〜0.8秒程度から試す。会話の返信待ちも、読める時間とは別にする。クイズの思考時間は、問題と全選択肢の入場が終わってから計る。「テンポを上げる」を「全部の間を削る」と解釈しない。

## 5. 画面の余白

1080×1920の試作では、上260px・下400px・左80px・右160pxを重要情報から避ける初期値とする。残る領域は840×1260px。背景や飾りまでこの範囲に制限する必要はない。

投稿先のUIは媒体・端末・表示状態で変わりうる。この数値で絶対に重ならないとは説明しない。投稿先が決まったら、実画面または確認できる最新の仕様で見直す。字幕・投稿説明・右側ボタンと重ならないか確認する。投稿先未確認なら検品記録に残す。

## 6. Remotionで制作するとき

文字・吹き出し・ボタン・ゲージは、原則として編集可能なReact/HTML/SVGの独立レイヤーで作る。写真や漫画など元から画像である素材は画像のままでよい。

文字主体の動画を、ページ全体をPNGにして拡大するだけの構成で代替しない。ユーザーがスライドショーを求める場合や明示的に許容した場合は例外。画像で焼き付いた文字を編集可能な文字レイヤーと説明しない。

アニメーションはRemotionのフレーム時刻に同期させる。Web向けCSSアニメーションやタイマーの例を、そのまま書き出しに使わない。APIは制作環境に実際に入っているバージョンの公式資料で確認し、関連パッケージのバージョンを揃えて固定する。根拠のない最新バージョン番号を書かない。

音声がある場合は実音声の長さと発話タイミングを確認する。原稿文字数で作った仮のタイムスタンプを実測値と呼ばない。元資料の `--with-timestamps` には効かない旨の注記があるので、実際のスクリプトと出力を確認する。

## 7. 書き出し後の検品

まず実際の台本でプレビューを作り、修正してから本書き出しする。静止画の確認だけでタイミングを合格にしない。

- [ ] 冒頭・各シーンの入場途中・最大文字量の状態・オチ／正解表示・最終フレームの静止画を確認した。
- [ ] 全尺を通常速度かつ無音で確認した。読めない箇所、唐突なスクロール、早すぎるオチがない。
- [ ] 音声付きの場合、全尺を音ありでも確認した。字幕・話者・効果音・音量・終端切れに問題がない。
- [ ] 文字切れ、見切れ、重なり、意図しない改行、フォントの置換がない。フォントの読み込み完了後に書き出した。
- [ ] 出力ファイルの実際の縦横サイズ・fps・尺・コーデック・音声の有無を検査した。ソースの設定値だけで実出力を説明していない。
- [ ] 投稿先UIとの重なりを確認した。未確認なら明記した。
- [ ] 原稿の意味、架空表示、英語の正確さ、実在アプリの機能や個人情報を形式に応じて確認した。
- [ ] MP4と対応するソース・台本が同じ版で、再書き出しに必要な素材参照が揃っている。フォントファイルや秘密情報を添付していない。

## 8. 完了報告の書き方

「企画のみ」「台本作成」「実装済み・未書き出し」「書き出し済み」「検品済み」を区別する。Remotion以外で作った動画をRemotionで書き出したと説明しない。完成していないMP4へのリンクは作らない。

未検証事項があれば残す。AIに別の評価役を与えたレビューを、人間の専門家による確認や実際の視聴者テストと呼ばない。再生維持率や売上の改善は、実際のデータがない限り実績として説明しない。

このリポジトリの `Shorts guide checks` はガイドのリンク・ルーティングと元資料の保持を検査する。動画の読みやすさ、英語の正確さ、Remotionの動作、MP4の品質を自動で保証するものではない。
