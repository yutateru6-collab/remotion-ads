# READON Promo 改善記録

## V1
- 実READON画面をPlaywrightで取得する基盤を作成。
- 弱点: 画面＋字幕に近く、映像言語と音が弱かった。

## V2
- 10ショット前後へ増加。
- 2.5D風、モーショングラフィックス、AIナレーション、BGM/SFXを追加。
- 良かった点: Pain→Transformation構造、実画面の信頼性。
- 問題:
  - Linuxレンダーで日本語フォントがCJK fallbackに落ちうる構成。
  - 26〜37px程度の補助文字がスマホで小さい。
  - 30秒は説明感が出やすい。
  - 英語の小見出しが多く、日本語視聴者の視線を分散。
  - CTAでURLが視覚的に強すぎた。

## V3 方針
- FontsourceでZen Kaku Gothic New / BIZ UDPGothicを自己ホスト。
- 22秒へ圧縮。
- 主見出し82〜106px、補助50px前後。
- 冒頭2.5秒以内にREADON名を表示。
- TikTok右端・最下部から重要情報を退避。
- CTAは「READONを開く」を主役にする。
- ナレーションを短く再生成し、BGMを弱める。

次回の改善時はV3完成MP4の弱点をこのファイルに追記する。


## V3 QA round 2
- 実レンダー後の代表静止画で再検品。
- 冒頭補助文が大見出しと重なったため削除。1画面1メッセージを優先。
- Reader下部の「READ / 訳 / 解説」説明が実画面と重なったため削除。見出しだけで意味を伝える構成へ簡略化。
- CTA下の長いURLが2行に折り返して視覚的に弱かったため動画上から削除。「READONを開く」を主CTAに固定。
- Materialize場面の補助文も重複していたため削除し、余白を増やした。
- 学び: 情報を足すより、重複説明を削って主役を1つにする方が短尺広告の品質が上がる。


## V3 客観レビュー
- 総合は約64点。フォントそのものは改善したが、広告としてはまだ弱い。
- 問題:
  - 日本語が「しんど / くない？」など単語途中で自動改行される。
  - 端末全体表示が長く、訳・解説の変化が小さく見える。
  - 設定3枚重ねで視線が分散。
  - モンタージュで大見出し・3画面・補助文が競合。
  - 22秒の中に静止気味の区間が多い。
  - 最終音量が約 -24.9 LUFS と小さかった。
  - 押せない「READONを開く」ボタンは動画上ではUI誤認の余地がある。

## V4 方針
- 16.5秒へ短縮。
- 見出しは意味単位で手動改行し、単語途中の改行を禁止。
- 設定は英検2級 → 400語 → 解説キャラを1つずつ約0.6秒で見せる。
- Readerは英文カードの上半分を大きくクロップし、訳・解説の変化を主役化。
- 3画面モンタージュを廃止。Payoffは1枚の実画面＋1メッセージのみ。
- 偽ボタンCTAを廃止。
- 完成MP4をFFmpeg loudnormで -16 LUFS / TP -1.5dBへ正規化。


## V4 客観レビューからV5へ
- V4はタイポ・情報整理・音量は改善したが、音声が映像と意味単位でずれていた。
- 原因: 4本の長いナレーションが複数ショットをまたいでおり、特にclosing音声がロゴ画面より約2秒先行。
- 英語学習TikTokの調査から、機能説明より「先に1問学ばせる」構造を採用。
- V5:
  - 15秒
  - survived の3択クイズから開始
  - 4秒以内に答え
  - その後READONへ接続
  - 9本の短い音声を各ショットへ1対1対応
  - ffprobeによるAudio Sync Validator追加
  - 1秒刻みcontact sheetをCI生成
