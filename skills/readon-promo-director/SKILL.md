# READON Promo Director

READONの宣伝動画を作成・改善するときは、実装前に現行版のMP4、代表静止画、実コードを確認する。

## 目的

単なる「アプリ画面＋字幕」ではなく、
「興味のない英語長文がしんどい → 自分の好きな題材に変える → 読める → 訳・解説で理解できる」
という感情変化を短尺で伝える。

## 日本語タイポグラフィ

- 見出し: Zen Kaku Gothic New 900
- 補助字幕 / UI説明: BIZ UDPGothic 700
- OSのCJK fallbackに依存しない。Fontsource等で動画プロジェクト内に自己ホストする。
- 見出しの基準: 82〜110px（1080x1920）
- 補助字幕の基準: 48〜56px
- 40px未満の日本語説明文は原則使用しない。
- 読ませる文章量を増やすより、文を削る。
- 日本語は不自然な均等割り、変な字間、漢字だけ太く見えるfallbackを禁止。
- 1画面の主メッセージは原則1つ。
- 日本語見出しは意味単位で手動改行する。単語途中の自動改行を禁止し、`word-break: keep-all` + `white-space: nowrap`相当で固定する。

## TikTok / Reels向け配置

- 9:16 / 1080x1920
- 重要情報を右端と最下部へ置かない。
- 右側は投稿UIと競合しやすいので、主見出し・CTAの中心領域に使わない。
- 下部はキャプション・UIと競合するため、重要字幕は十分上へ置く。
- 冒頭2.5〜3秒以内にREADON名と視聴理由を提示する。

## ショット設計

- Pain → transformation → customization → reading → assistance → close
- ただのスクリーンショット切替にしない。
- 実画面は「何を押したか」「何が変わったか」が分かる順序で見せる。
- Readerは端末全体を見せ続けず、英文・訳・解説の差が分かる領域へ局所ズームする。
- 複数の設定画面を重ねて同時に見せない。1操作1主役で切る。
- ショットごとに主役を1つにする。
- 同じ構図を3回以上続けない。
- 15〜17秒版を優先候補とし、意味のない静止時間を削る。
- 押せない偽ボタン風CTAは使わない。
- 2.5D、軽いparallax、camera pushは可。意味のない常時ズームは禁止。
- 実在しないUI、実績、レビュー、利用者数を追加しない。

## 音

- ナレーションを最優先。
- BGMはナレーションより明確に後ろへ置く。
- SFXは画面切替・クリック・決めだけ。鳴らしすぎない。
- 完成後に音声streamの存在、ピーク、聞き取りやすさを確認する。
- 短尺SNS版は最終MP4でラウドネスを測定する。必要ならFFmpeg loudnormで目標を -16 LUFS前後、True Peak -1.5dB以下へ整える。

## QA

最低限:
- TypeScript
- 本番READON実画面キャプチャ
- console error / page error
- 9〜12代表フレーム
- MP4
- ffprobe
- 2秒刻み程度のコンタクトシート
- 日本語字形を実画像で確認
- 改行・重なり・TikTok UI競合・小さすぎる文字を目視
- 「Actions成功」と「映像品質合格」を区別する

## 改善ループ

1. 現行版を目視
2. 問題を具体化
3. CHANGELOGに仮説を書く
4. 変更
5. 再レンダー
6. 静止画 + 完成MP4を再確認
7. 問題と学びをCHANGELOGへ追加

毎回このSkill自体も更新し、同じ失敗を繰り返さない。
